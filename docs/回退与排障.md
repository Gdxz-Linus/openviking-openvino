# 回退与排障

## 一、从进程内回退到 HTTP

适用：补丁打不上、驱动异常、OpenVINO 版本不兼容，需要临时换回独立服务。

### 步骤

1. 启动嵌入服务：

```bash
python http-server/embed_server.py --model-dir D:/OpenViking/models/harrier-ov-int8 --port 8010
curl --noproxy '*' http://127.0.0.1:8010/health
```

2. 备份当前配置，换成 HTTP 版：

```bash
cp ov.conf ov.conf.bak
cp configs/ov.conf.http.example ov.conf
```

3. 应用保活补丁（如果还没打）：

```bash
python patches/patch_http_keepalive.py
```

4. 重启 OpenViking。

### 回退后的代价

| 指标 | 进程内 | HTTP |
| --- | --- | --- |
| 检索中位 | 43 ms | 273 到 386 ms |

慢 6 到 9 倍，属于应急方案。

### 必须注意

每次重启机器或重启 OpenViking 之前，先确认 8010 服务在运行，否则检索直接报连接失败。

## 二、从两种形态回退到官方 llama-cpp

如果 OpenVINO 方案整体不可用：

1. 还原 `local_embedders.py`：

```bash
python patches/patch_openvino.py --revert
```

或者直接用官方 wheel 覆盖：

```bash
pip install --force-reinstall openviking==0.5.3
```

2. 配置改成官方默认：

```json
"embedding": {
  "dense": {
    "provider": "local",
    "model": "bge-small-zh-v1.5-f16",
    "dimension": 512
  }
}
```

3. 清空向量库并重建。维度从 1024 变回 512，旧向量不能复用。

```bash
# 先确认 data 目录位置，删前务必备份
```

4. 重启服务。

注意：官方默认模型首次启动会自动下载约 100 MB 到 `~/.cache/openviking/models`。

## 三、排障清单

### 启动即失败：找不到模型

```
OpenVINO IR not found: ...
```

核对三件事：

| 检查项 | 期望 |
| --- | --- |
| `cache_dir` | 指向模型根目录，如 `D:/OpenViking/models` |
| 模型子目录名 | 与 `em_model_dir` 一致，如 `harrier-ov-int8` |
| 目录内文件 | `int8/openvino_model.xml`、`int8/openvino_model.bin`、`int8/tokenizer.json` |

### 维度不一致

```
ValueError: dimension mismatch
```

`ov.conf` 的 `dimension` 必须等于模型实际维度。harrier-ov-int8 是 1024，bge-small 是 512。改配置后需要重建向量库。

### 补丁打不上

```
[失败] spec 字段：锚点匹配 0 处，不是官方 0.5.3 原版
```

这说明 OpenViking 版本与本补丁适配的 0.5.3 结构不一致。处理顺序：

1. 不要强行改文件。
2. 先确认版本：`pip show openviking`。
3. 若版本高于 0.5.3，等待本项目更新适配，或在项目仓库提出适配请求。
4. 若已解压官方 wheel 对比结构，可按新结构修改 `patch_openvino.py` 中用于定位的代码片段后重试。修改前先备份。

### 安装向导报「目标版本不符」

```
  [错误]  补丁目标                 目标版本不符

  当前 OpenViking 版本：0.5.3
  当前字节：17495
  当前 SHA-256：d49bfa71...
  本补丁适配版本：OpenViking 0.5.3 官方原版
  适配文件字节：8774
  适配文件 SHA-256：adf69925...
```

版本对得上但文件对不上，说明 `local_embedders.py` 被其它补丁或手工改动修改过。向导会给出恢复命令：

```bash
<OpenViking 的 python.exe> -m pip install --force-reinstall --no-deps openviking==0.5.3
```

执行后该文件恢复成官方原版，所有补丁改动消失，重新运行向导即可。

如果显示的是版本本身不对（例如 `当前 OpenViking 版本：0.5.5`），按提示安装 0.5.3，或在项目仓库提出该版本的适配请求。

### 安装向导报找不到 OpenViking

```
  [错误] 未找到 OpenViking 0.5.3 安装目录或读取不到版本。
```

向导不猜测安装位置。用 `--ov-home` 指明，或设置环境变量：

```bash
python install.py --ov-home /path/to/OpenViking
```

```bash
export OPENVIKING_HOME=/path/to/OpenViking    # Linux 与 macOS
set OPENVIKING_HOME=D:/OpenViking             # Windows cmd
$env:OPENVIKING_HOME = 'D:/OpenViking'        # PowerShell
```

### 安装向导报 agent 未接入

```
  [错误]  agent 侧插件            未接入
```

至少需要一个 agent 已接入 OpenViking。判定方式：

| agent | 检查位置 |
| --- | --- |
| Hermes | `%LOCALAPPDATA%\hermes\plugins\openviking\` 是否存在 |
| DSH | profile 的 `package.json` 依赖里是否含 `@openviking/` |

缺哪个就在那个 agent 里装好 OpenViking 记忆插件，确认能正常读写记忆后重跑向导。

### GPU 检测不到

```bash
python -c "import openvino as ov; print(ov.Core().available_devices)"
```

只返回 `CPU` 时：

| 原因 | 处理 |
| --- | --- |
| 显卡驱动未安装或不匹配 | 装 Intel 官方驱动 |
| 核显被禁用 | 在 BIOS 或系统里启用 |
| OpenVINO 版本过旧 | 升级到 2024 以上 |

补丁会自动改用 CPU，功能不受影响，只是处理长文本时慢一些。

### 记忆抽取持续失败

现象：对话正常，但记忆条目不增加，日志里 `session_commit` 报错。

| 原因 | 处理 |
| --- | --- |
| `ov.conf` 的 `vlm` 段与实际通道不符 | 装 `vlm-follow` 插件，或手工改配置 |
| 上游模型服务不可达 | 先 `curl` 该端点确认 |
| API key 过期 | 更新 key 后等 30 秒重载 |

OpenViking 每 30 秒重载配置，改完不需要重启。

### 嵌入服务长时间运行后退化

HTTP 形态实测出现过连续 2.5 小时后单次耗时从 2 ms 涨到 122 ms、重启恢复的情况。处理：

1. 定期重启嵌入服务（如每天一次）。
2. 或者直接改用进程内形态，从根上避免。

## 四、数据安全

| 操作 | 风险 | 建议 |
| --- | --- | --- |
| 换嵌入模型或维度 | 旧向量作废 | 先备份 `data` 目录，再重建 |
| 删除记忆文件 | 只删磁盘文件会留下幽灵向量 | 必须走 OpenViking 的删除接口，不要直接 `rm` |
| 升级 OpenViking | 补丁丢失 | 升级后立刻重放补丁再启动 |
