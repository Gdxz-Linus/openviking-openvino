# 回退与排障

## 一、从进程内回退到 HTTP

适用：补丁打不上、驱动异常、OpenVINO 版本不兼容，需要临时换回独立服务。

### 步骤

1. 启动嵌入服务：

```bash
python http-server/embed_server.py --model-dir D:/OpenViking/models/harrier-ov-int8 --port 8010
curl --noproxy '*' http://127.0.0.1:8010/health
```

2. 备份当前配置，换成 HTTP 版：

```bash
cp ov.conf ov.conf.bak
cp configs/ov.conf.http.example ov.conf
```

3. 应用保活补丁（如果还没打）：

```bash
python patches/patch_http_keepalive.py
```

4. 重启 OpenViking。

### 回退后的代价

| 指标 | 进程内 | HTTP |
| --- | --- | --- |
| 检索中位 | 43 ms | 273 到 386 ms |

慢 6 到 9 倍，属于应急方案。

### 必须注意

每次重启机器或重启 OpenViking 之前，先确认 8010 服务在运行，否则检索直接报连接失败。

## 二、从两种形态回退到官方 llama-cpp

如果 OpenVINO 方案整体不可用：

1. 还原 `local_embedders.py`：

```bash
python patches/patch_openvino.py --revert
```

或者直接用官方 wheel 覆盖：

```bash
pip install --force-reinstall openviking==0.5.3
```

2. 配置改成官方默认：

```json
"embedding": {
  "dense": {
    "provider": "local",
    "model": "bge-small-zh-v1.5-f16",
    "dimension": 512
  }
}
```

3. 清空向量库并重建。维度从 1024 变回 512，旧向量不能复用。

```bash
# 先确认 data 目录位置，删前务必备份
```

4. 重启服务。

注意：官方默认模型首次启动会自动下载约 100 MB 到 `~/.cache/openviking/models`。

## 三、排障清单

### 启动即失败：找不到模型

```
OpenVINO IR not found: ...
```

核对三件事：

| 检查项 | 期望 |
| --- | --- |
| `cache_dir` | 指向模型根目录，如 `D:/OpenViking/models` |
| 模型子目录名 | 与 `em_model_dir` 一致，如 `harrier-ov-int8` |
| 目录内文件 | `int8/openvino_model.xml`、`int8/openvino_model.bin`、`int8/tokenizer.json` |

### 维度不一致

```
ValueError: dimension mismatch
```

`ov.conf` 的 `dimension` 必须等于模型实际维度。harrier-ov-int8 是 1024，bge-small 是 512。改配置后需要重建向量库。

### 补丁打不上

```
锚点匹配 0 次，上游可能已改动
```

说明 OpenViking 版本变了。处理顺序：

1. 不要强行改。
2. 用 `git diff` 或解压官方 wheel，对比 `local_embedders.py` 的结构变化。
3. 调整 `patch_openvino.py` 的锚点后重试。

### GPU 检测不到

```bash
python -c "import openvino as ov; print(ov.Core().available_devices)"
```

只返回 `CPU` 时：

| 原因 | 处理 |
| --- | --- |
| 显卡驱动未安装或不匹配 | 装 Intel 官方驱动 |
| 核显被禁用 | 在 BIOS 或系统里启用 |
| OpenVINO 版本过旧 | 升级到 2024 以上 |

补丁会自动回落 CPU，功能不受影响，只是长文本变慢。

### 记忆抽取持续失败

现象：对话正常，但记忆条目不增加，日志里 `session_commit` 报错。

| 原因 | 处理 |
| --- | --- |
| `ov.conf` 的 `vlm` 段与实际通道不符 | 装 `vlm-follow` 插件，或手工改配置 |
| 上游模型服务不可达 | 先 `curl` 该端点确认 |
| API key 过期 | 更新 key 后等 30 秒重载 |

OpenViking 每 30 秒重载配置，改完不需要重启。

### 嵌入服务长时间运行后退化

HTTP 形态实测出现过连续 2.5 小时后单次耗时从 2 ms 涨到 122 ms、重启恢复的情况。处理：

1. 定期重启嵌入服务（如每天一次）。
2. 或者直接改用进程内形态，从根上避免。

## 四、数据安全

| 操作 | 风险 | 建议 |
| --- | --- | --- |
| 换嵌入模型或维度 | 旧向量作废 | 先备份 `data` 目录，再重建 |
| 删除记忆文件 | 只删磁盘文件会留下幽灵向量 | 必须走 OpenViking 的删除接口，不要直接 `rm` |
| 升级 OpenViking | 补丁丢失 | 升级后立刻重放补丁再启动 |
