# 部署指南

本指南给出两条路径：用安装向导一条命令完成，或按手工步骤逐步操作。

## 一、用安装向导

推荐先用向导，它会自动完成配置写入、打补丁、装插件与验证。

```bash
python install.py --dry-run --ov-home /path/to/OpenViking   # 先看清楚要做什么
python install.py --ov-home /path/to/OpenViking             # 真正执行
```

Windows 下也可以直接双击 `install.cmd`，或在 PowerShell 里运行 `install.ps1`。

向导会依次询问嵌入方式、模型、要装插件的 agent，然后打印确认清单。每一项改动前都会备份，任一步失败自动还原到操作前状态。

以下内容由向导自动处理，不需要额外操作：

| 内容 | 说明 |
| --- | --- |
| OpenVINO Runtime 与 tokenizers | 未安装时自动装到 OpenViking 的 Python 环境，官方源失败时依次尝试国内镜像 |
| HTTP 连接保活补丁 | 始终安装，只在 HTTP 形态下参与推理 |
| 配置写入 | 已有 `ov.conf` 时只改 `embedding` 段并先备份，没有则按模板生成 |

向导不做的事：不代装 OpenViking、Hermes、DSH 及其插件，不下载模型。这些需要你先自行准备。

如果你更希望手工操作、或者想了解每一步具体在改什么，看下面的手工步骤。

## 二、前置条件

| 项目 | 要求 |
| --- | --- |
| OpenViking | 0.5.3 官方原版（补丁直接适配，无需前置改造） |
| Python | 3.13（OpenViking 自带 venv 即可） |
| OpenVINO Runtime | 2024 及以上，GPU 形态需要安装对应驱动 |
| 模型 | OpenVINO IR（`openvino_model.xml` + `.bin` + `tokenizer.json`） |
| 硬件 | Intel CPU 可跑；核显或 NPU 需要 OpenVINO 能识别到设备 |

检查设备是否可用：

```bash
python -c "import openvino as ov; print(ov.Core().available_devices)"
```

输出里应该能看到 `GPU` 或 `CPU`。没有 GPU 时补丁会自动改用 CPU，只是速度慢一些，功能不受影响。

### 平台支持

| 平台 | 支持 | 说明 |
| --- | --- | --- |
| Windows 10/11 (x86_64) | 支持 | 完整支持，含 Intel 核显 GPU 加速 |
| Linux (x86_64) | 支持 | 完整支持，GPU 需装 Intel 显卡驱动 |
| macOS | 不支持 | OpenVINO 在 macOS 只提供 CPU 推理，拿不到 GPU 加速收益 |
| ARM (任何平台) | 不支持 | OpenVINO 在 ARM 上无 GPU 支持 |

Linux 下使用 GPU 形态前，需要先安装 Intel 显卡驱动，并确认 `ov.Core().available_devices` 能列出 `GPU`。

## 三、准备模型

各模型的目录结构不同，按选定的模型摆放。`cache_dir` 在 `ov.conf` 的 `embedding.dense.cache_dir` 指定，例如 `D:/OpenViking/models`。

harrier-ov-int8（IR 在 `int8/` 子目录，tokenizer 一套平铺在上一级）：

```
<cache_dir>/harrier-ov-int8/
├── int8/
│   ├── openvino_model.xml
│   ├── openvino_model.bin
│   └── tokenizer.json
```

Qwen3-Embedding-0.6B、bge-m3、SEA-LION 三款（IR 与 tokenizer 都平铺在模型目录根下）：

```
<cache_dir>/<模型名>/
├── openvino_model.xml
├── openvino_model.bin
└── tokenizer.json
```

embeddinggemma-2（三塔结构，只要文本塔）：

```
<cache_dir>/embeddinggemma-2-openvino-int8/
├── text_int8.xml
├── text_int8.bin
└── tokenizer.json
```

获取与导出方法见 `models/模型获取.md`。

## 四、进程内形态

### 4.1 打补丁

```bash
python patches/patch_openvino.py --check
python patches/patch_openvino.py
```

脚本会改 `site-packages/openviking/models/embedder/local_embedders.py` 七处：

1. `LocalModelSpec` 增加 `backend`、`ov_model_dir`、`ov_query_task` 三个字段
2. 模型表增加五款 OpenVINO 模型（含 `harrier-ov-int8`）
3. `__init__` 按 `backend` 分流
4. 新增 OpenVINO 加载与推理实现
5. `_embed_formatted_text` 分流
6. `embed` 增加查询前缀处理
7. `close` 分流

### 4.2 配置

复制 `configs/ov.conf.local.example` 到实际位置，改三处：

| 字段 | 说明 |
| --- | --- |
| `embedding.dense.cache_dir` | 模型根目录 |
| `embedding.dense.model` 与 `embedding.dense.dimension` | 必须成对写对：harrier、Qwen3、bge-m3、SEA-LION 四款是 1024，embeddinggemma-2 是 768。维度写错启动即报错 |
| `vlm.api_base` / `api_key` | 记忆抽取用的大模型端点 |

池化方式、是否归一化、查询前缀均由补丁按模型名自动决定，配置里不用写。

### 4.3 启动与验证

```bash
# 启动服务（按自己的部署方式）
D:\OpenViking\venv\Scripts\python.exe -m openviking_cli.server_bootstrap
```

启动日志应出现：

```
OpenVINO embedder ready: model=harrier-ov-int8 device=GPU compile=28.4s max_tokens=4096
```

首次启动编译耗时较长（约 28 秒），之后从 `ov_cache` 读取缓存。

验证维度与推理：

```bash
curl -s http://127.0.0.1:1933/health
```

返回 `healthy: true` 即正常。

## 五、HTTP 形态

### 5.1 启动嵌入服务

```bash
python http-server/embed_server.py --model harrier-ov-int8 --model-dir D:/OpenViking/models/harrier-ov-int8 --port 8010
```

`--model` 必须与服务端实际加载的模型一致（可选五款预设之一）；IR 文件名各款不同，服务按预设自动定位。可用 `--model-xml` 与 `--dimension` 覆盖预设值。

服务提供三个端点：

| 端点 | 用途 |
| --- | --- |
| `GET /health` | 健康检查 |
| `GET /v1/models` | 模型列表（兼容 OpenAI 格式） |
| `POST /v1/embeddings` | 嵌入接口 |

### 5.2 打保活补丁

```bash
python patches/patch_http_keepalive.py
```

不改这个补丁时，批量写入会因连接反复过期出现大量慢调用（实测 560 次，单次约 7.8 秒）。

### 5.3 配置

复制 `configs/ov.conf.http.example`，注意：

| 字段 | 值 |
| --- | --- |
| `embedding.dense.provider` | `openai` |
| `embedding.dense.api_base` | `http://127.0.0.1:8010/v1` |
| `embedding.dense.api_key` | 任意非空字符串，本地服务不校验 |
| `embedding.dense.dimension` | 1024 |

### 5.4 启动顺序

先起 8010 嵌入服务，再起 OpenViking。反过来会导致启动时嵌入探测失败。

## 六、升级后的恢复

```bash
# 1. 升级
pip install --upgrade openviking

# 2. 重放补丁
python patches/patch_openvino.py
python patches/patch_http_keepalive.py    # 仅 HTTP 形态

# 3. 重启服务
```

补丁脚本可重复执行。运行前先 `--check`，确认当前状态。若报「未打补丁」但文件结构与官方 0.5.3 不符，脚本报错停止、不写入文件，此时对照 `docs/回退与排障.md` 核对。

升级后也可以直接重跑安装向导，它会识别到补丁丢失并重新应用。

## 七、验证范围说明

安装向导提供了一部分自动化验证，也要明确它没有覆盖什么。

已用自动化手段验证过的内容：

| 项目 | 手段 |
| --- | --- |
| 补丁目标三态判定 | 单元测试 |
| 配置合并与 JSON 校验 | 单元测试 |
| 模型文件齐全性检查 | 单元测试 |
| 自定义模型四项探测 | 单元测试 |
| 备份文件命名 | 单元测试 |
| `--dry-run` 不产生副作用 | 单元测试与实跑对比哈希 |
| 补丁应用与重复执行 | 在官方 0.5.3 原版副本上实跑 |
| 五款预设与自定义模型的真实推理 | 真实模型加载并比对向量 |

没有在真实安装流程中验证过的内容：

| 项目 | 原因 |
| --- | --- |
| 在目标机器上实际下载 OpenVINO | 依赖网络与磁盘 |
| 真实写入生产 `ov.conf` 并重启生效 | 会改动运行中的实例 |
| 真实安装插件到 Hermes 与 DSH | 会改动宿主配置 |

这几项需要你在自己的环境里跑一次确认。第一次建议先加 `--dry-run` 看清动作，再正式执行。

## 八、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `Unknown local embedding model` | 补丁没打或被打回 | 重跑 `patch_openvino.py` |
| 启动报 `OpenVINO IR not found` | `cache_dir` 或模型目录名不对，或 IR 文件名与该模型的预设不一致 | 核对路径与目录结构；embeddinggemma-2 的文本塔叫 `text_int8.xml` |
| 报维度不一致 | `dimension` 与模型不符 | 改成模型实际维度（embeddinggemma-2 是 768，其余四款 1024） |
| 检索结果明显变差但无报错 | 池化方式或归一化与该模型不匹配 | 确认 `ov.conf` 的 `model` 写的是模型表里的名字，补丁会据此自动选池化 |
| GPU 不可用，自动改用 CPU | 驱动或设备未就绪 | 查 `ov.Core().available_devices` |
| 检索慢到几百毫秒 | 走的是 HTTP 形态 | 切回进程内形态 |
| 记忆抽取持续失败 | `vlm` 段与实际通道不符 | 装 `vlm-follow` 插件或手工改配置 |
