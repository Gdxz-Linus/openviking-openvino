# 部署指南

## 一、前置条件

| 项目 | 要求 |
| --- | --- |
| OpenViking | 0.5.3（补丁锚点按该版本编写） |
| Python | 3.13（OpenViking 自带 venv 即可） |
| OpenVINO Runtime | 2024 及以上，GPU 形态需要安装对应驱动 |
| 模型 | OpenVINO IR（`openvino_model.xml` + `.bin` + `tokenizer.json`） |
| 硬件 | Intel CPU 可跑；核显或 NPU 需要 OpenVINO 能识别到设备 |

检查设备是否可用：

```bash
python -c "import openvino as ov; print(ov.Core().available_devices)"
```

输出里应包含 `GPU` 或 `CPU`。没有 GPU 时补丁会自动回落到 CPU，只损失速度，不影响功能。

## 二、准备模型

模型目录结构：

```
<cache_dir>/harrier-ov-int8/
├── int8/
│   ├── openvino_model.xml
│   ├── openvino_model.bin
│   └── tokenizer.json
```

`cache_dir` 在 `ov.conf` 的 `embedding.dense.cache_dir` 指定，例如 `D:/OpenViking/models`。

获取与导出方法见 `models/模型获取.md`。

## 三、进程内形态

### 3.1 打补丁

```bash
python patches/patch_openvino.py --check
python patches/patch_openvino.py
```

脚本会改 `site-packages/openviking/models/embedder/local_embedders.py` 七处：

1. `LocalModelSpec` 增加 `backend`、`ov_model_dir`、`ov_query_task` 三个字段
2. 模型表增加 `harrier-ov-int8` 表项
3. `__init__` 按 `backend` 分流
4. 新增 OpenVINO 加载与推理实现
5. `_embed_formatted_text` 分流
6. `embed` 增加查询前缀处理
7. `close` 分流

### 3.2 配置

复制 `configs/ov.conf.local.example` 到实际位置，改三处：

| 字段 | 说明 |
| --- | --- |
| `embedding.dense.cache_dir` | 模型根目录 |
| `embedding.dense.dimension` | 必须与模型一致，harrier-ov-int8 是 1024 |
| `vlm.api_base` / `api_key` | 记忆抽取用的大模型端点 |

### 3.3 启动与验证

```bash
# 启动服务（按自己的部署方式）
D:\OpenViking\venv\Scripts\python.exe -m openviking_cli.server_bootstrap
```

启动日志应出现：

```
OpenVINO embedder ready: model=harrier-ov-int8 device=GPU compile=28.4s max_tokens=4096
```

首次启动编译耗时较长（约 28 秒），之后从 `ov_cache` 读取缓存。

验证维度与推理：

```bash
curl -s http://127.0.0.1:1933/health
```

返回 `healthy: true` 即正常。

## 四、HTTP 形态

### 4.1 启动嵌入服务

```bash
python http-server/embed_server.py --model-dir D:/OpenViking/models/harrier-ov-int8 --port 8010
```

服务提供三个端点：

| 端点 | 用途 |
| --- | --- |
| `GET /health` | 健康检查 |
| `GET /v1/models` | 模型列表（兼容 OpenAI 格式） |
| `POST /v1/embeddings` | 嵌入接口 |

### 4.2 打保活补丁

```bash
python patches/patch_http_keepalive.py
```

不改这个补丁时，批量写入会因连接反复过期出现大量慢调用（实测 560 次，单次约 7.8 秒）。

### 4.3 配置

复制 `configs/ov.conf.http.example`，注意：

| 字段 | 值 |
| --- | --- |
| `embedding.dense.provider` | `openai` |
| `embedding.dense.api_base` | `http://127.0.0.1:8010/v1` |
| `embedding.dense.api_key` | 任意非空字符串，本地服务不校验 |
| `embedding.dense.dimension` | 1024 |

### 4.4 启动顺序

先起 8010 嵌入服务，再起 OpenViking。反过来会导致启动时嵌入探测失败。

## 五、升级后的恢复

```bash
# 1. 升级
pip install --upgrade openviking

# 2. 重放补丁
python patches/patch_openvino.py
python patches/patch_http_keepalive.py    # 仅 HTTP 形态

# 3. 重启服务
```

补丁脚本幂等，重复执行安全。锚点不匹配说明上游代码结构变了，此时停止操作，对照 `docs/回退与排障.md` 人工核对。

## 六、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报找不到 `harrier-ov-int8` | 补丁没打或被打回 | 重跑 `patch_openvino.py` |
| 报 `OpenVINO IR not found` | `cache_dir` 或模型目录名不对 | 核对路径与目录结构 |
| 报维度不一致 | `dimension` 与模型不符 | 改成模型实际维度 |
| GPU 不可用，回落 CPU | 驱动或设备未就绪 | 查 `ov.Core().available_devices` |
| 检索慢到几百毫秒 | 走的是 HTTP 形态 | 切回进程内形态 |
| 记忆抽取持续失败 | `vlm` 段与实际通道不符 | 装 `vlm-follow` 插件或手工改配置 |
