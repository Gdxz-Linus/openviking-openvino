# 模型获取

本仓库不自带模型权重。需要准备 OpenVINO IR 格式的嵌入模型，五款模型的目录结构并不相同，见下。

## 一、目录结构

各模型的摆放位置不同，由补丁与服务按模型名自动查找，按对应结构放置即可。

harrier-ov-int8（IR 在 `int8/` 子目录，tokenizer 一套平铺在上一级）：

```
<cache_dir>/harrier-ov-int8/
├── int8/
│   ├── openvino_model.xml      # 模型结构
│   ├── openvino_model.bin      # 权重
│   └── tokenizer.json          # 分词器
```

Qwen3-Embedding-0.6B、bge-m3、SEA-LION 三款（IR 与 tokenizer 平铺在模型目录根下）：

```
<cache_dir>/<模型名>/
├── openvino_model.xml
├── openvino_model.bin
└── tokenizer.json
```

embeddinggemma-2（三塔结构，只要文本塔）：

```
<cache_dir>/embeddinggemma-2-openvino-int8/
├── text_int8.xml
├── text_int8.bin
└── tokenizer.json
```

`cache_dir` 由 `ov.conf` 的 `embedding.dense.cache_dir` 指定。

## 二、可选模型

五款都可以直接用，任选一个，都是 int8 格式。国内网络用 hf-mirror 镜像地址。

| 模型 | 权重 | 维度 | 上下文 | 语言 | 下载 |
| --- | --- | --- | --- | --- | --- |
| Qwen3-Embedding-0.6B | 596M | 1024 | 32768 | 100 多种语言 | [下载](https://hf-mirror.com/OpenVINO/Qwen3-Embedding-0.6B-int8-ov) |
| harrier-oss-v1-0.6b | 596M | 1024 | 32768 | 多语言 | [下载](https://hf-mirror.com/doldolggi/harrier-oss-v1-0.6b-OpenVINO) |
| bge-m3 | 568M | 1024 | 8192 | 多语言 | [下载](https://hf-mirror.com/OpenVINO/bge-m3-int8-ov) |
| SEA-LION-ModernBERT-Embedding-600M | 612M | 1024 | 8192 | 东南亚 11 种语言与中文 | [下载](https://hf-mirror.com/aisingapore/SEA-LION-ModernBERT-Embedding-600M-OV) |
| embeddinggemma-2 | 744M | **768** | 8192 | 100 多种语言 | [下载](https://hf-mirror.com/wesjos/embeddinggemma-2-openvino-int8) |

### 下载后的摆放方式

不需要统一改成同一种布局，补丁与服务按模型名查表定位。只做必要的一件事：把下载到的模型目录改成表里的模型名。

| 来源 | 仓库自带布局 | 需要做什么 |
| --- | --- | --- |
| harrier-oss-v1-0.6b | 自带 `int8/` 与 `int4/` 子目录 | 目录名改为 `harrier-ov-int8`，其余不动 |
| Qwen3-Embedding-0.6B、bge-m3 | 根目录平铺 xml 与 bin | 目录名改为表里的模型名，其余不动 |
| SEA-LION | 根目录平铺，另含 tokenizer 与 detokenizer | 目录名改为表里的模型名，其余不动 |
| embeddinggemma-2 | 文本、图像、音频三组文件分开 | 目录名改为 `embeddinggemma-2-openvino-int8`，只留文本那组 `text_int8.xml` 与 `.bin`，另两个塔可删 |

不要为了「统一结构」把 xml 与 bin 搬进 `int8/` 子目录。补丁按模型表里的文件名找 IR，搬动后会找不到。

### 有 int8 但格式不同，需转换

| 模型 | 参数量 | 维度 | int8 格式 | 仓库 |
| --- | --- | --- | --- | --- |
| Qwen3-Embedding-4B | 4B | 2560 | ONNX int8 | `daewooshen/Qwen3-Embedding-4B-INT8-ONNX`、`Jasai/Qwen3-Embedding-4B-INT8-ONNX`、`mariusbrt/Qwen3-Embedding-4B-ONNX-int8` |
| jina-embeddings-v3 | 570M | 1024 | MLX int8 | `arlenecc/jina-embeddings-v3-mlx-int8` |

这两款 OpenViking 不能直接加载，要先转成 OpenVINO IR，转完还得在补丁里加表项。

### 换成新模型必须重建向量库

维度与池化方式都可能变，旧向量不能复用。

补丁已内置上述五款，选其中任意一款只需在 `ov.conf` 中写对 `model` 与 `dimension`，无需自加表项。表外模型才需自行添加，并按实际维度、池化方式、是否归一化、查询前缀填全四项。填错不会报错，只会降低检索质量。


## 三、转换方法

用 OpenVINO 官方工具把原始模型导出成 IR：

```bash
pip install optimum[openvino]

# 国内网络建议先设镜像
export HF_ENDPOINT=https://hf-mirror.com

optimum-cli export openvino \
  --model microsoft/harrier-oss-v1-0.6b \
  --task feature-extraction \
  --weight-format int8 \
  D:/OpenViking/models/harrier-ov-int8
```

三个参数的含义：

| 参数 | 作用 | 不写会怎样 |
| --- | --- | --- |
| `--task feature-extraction` | 指定导出为嵌入任务 | 可能按文本生成任务导出，结构不符 |
| `--weight-format int8` | 量化到 int8 | 导出 fp32，体积约为四倍 |
| 输出目录 | IR 落地位置 | — |

转换完成后会得到一个含 `openvino_model.xml`、`.bin` 与 `tokenizer.json` 的目录，把目录名改成模型表里的名字即可。导出工具把文件都放在输出根目录下时，正好对应「平铺」那几款的布局，不需要搬动。

如果转换的是表外模型，用下面的 `custom` 入口，不需要改补丁代码。

## 三之二、使用自己准备的模型（custom）

补丁内置一条 `custom` 表项，用来挂载内置五款之外的 OpenVINO IR 模型。

### 配置

`ov.conf` 的 `embedding.dense` 写三项：

```json
"dense": {
  "provider": "local",
  "model": "custom",
  "dimension": 1024,
  "model_path": "D:/OpenViking/models/my-model/int8/openvino_model.xml"
}
```

其中 `model` 固定写 `custom`；`dimension` 填该模型的实际输出维度；`model_path` 填 IR 文件的绝对路径。

### 模型参数文件

池化、归一化、前缀这些参数不写在 `ov.conf` 里——那一层配置会丢弃不认识的字段。改在模型目录下放一个 `openvino_custom.json`，与 `tokenizer.json` 同级：

```json
{
  "pooling": "last",
  "normalize": true,
  "query_task": "",
  "query_prefix": "",
  "doc_prefix": ""
}
```

| 字段 | 取值 | 默认 |
| --- | --- | --- |
| `pooling` | `model` 模型自带池化；`last` 取最后一个词；`cls` 取第一个词；`mean` 取有效词平均 | `last` |
| `normalize` | 是否自行归一化 | `true` |
| `query_task` | 查询侧指令前缀的任务描述，会拼成 `Instruct: <任务>` 换行 `Query: <文本>` | 空 |
| `query_prefix` | 查询侧字面前缀，优先于 `query_task` | 空 |
| `doc_prefix` | 文档侧字面前缀 | 空 |

文件不存在时全部用默认值，启动日志会打一条警告。

### 怎么确定这几项

| 字段 | 判断方法 |
| --- | --- |
| `dimension` | 看模型的 `config.json` 里 `hidden_size`；多模态模型看 `text_config.hidden_size` |
| `pooling` | 有 `1_Pooling/config.json` 时看 `pooling_mode_lasttoken` / `pooling_mode_cls_token` / `pooling_mode_mean_tokens` 哪项为真；没有该文件且模型输出已是句子向量时填 `model` |
| `normalize` | 除 `model` 之外三种池化都需要归一化 |
| `query_task` | 看模型卡是否要求查询侧加指令前缀 |
| `doc_prefix` | 只有少数模型（如 embeddinggemma 系列）要求 |

填错不会报错，但向量会算错，表现为检索结果明显变差。改动后需要重建向量库。

### 已验证的行为

用内置的 Qwen3 模型冒充 custom 做过对照：把四项参数填成与内置表项一致后，custom 与内置表项产出的向量余弦为 1.0000000000，完全一致。池化方式与归一化开关单独改动时也都实际生效（三种池化的向量两两余弦分别为 0.41 与 0.78，归一化关闭时范数为 86.76）。


## 四、各模型的池化与前缀要求

五款模型的池化方式与前缀规则各不相同，用错不会报错，只会降低检索质量。补丁的表项已按模型写好，正常使用不需要手工处理；自行加表项时必须照下表填对。

| 模型 | 池化方式 | 需自行归一化 | 查询侧前缀 | 文档侧前缀 |
| --- | --- | --- | --- | --- |
| harrier-ov-int8 | 模型内置 | 否 | `Instruct: …\nQuery: ` | 无 |
| Qwen3-Embedding-0.6B-int8-ov | last-token（末个真实 token） | 是 | `Instruct: …\nQuery: ` | 无 |
| bge-m3-int8-ov | CLS（第 0 位） | 是 | 无（官方明确要求不加） | 无 |
| SEA-LION-ModernBERT-Embedding-600M-OV | mean（按 attention_mask 加权） | 是 | 无 | 无 |
| embeddinggemma-2-openvino-int8 | 模型内置 | 否 | `task: search result \| query: ` | `title: none \| text: ` |

关于 pad：补丁与服务均从模型自带的 `tokenizer_config.json` 读取 pad 配置，不写死某一模型的 pad id。分词器库不校验 pad id 是否越界，沿用其他模型的常量会静默出错。

## 五、磁盘占用

| 项目 | 体积 |
| --- | --- |
| harrier-ov-int8 模型 | 约 587 MB |
| Qwen3-Embedding-0.6B-int8-ov | 约 611 MB |
| bge-m3-int8-ov | 约 570 MB |
| SEA-LION-ModernBERT-Embedding-600M-OV | 约 675 MB |
| embeddinggemma-2-openvino-int8（仅文本塔） | 约 275 MB，全三塔 741 MB |
| OpenVINO 编译缓存 `ov_cache` | 约 2.1 GB，可删自动重建 |

模型体积随量化精度变化，int8 通常是 fp32 的四分之一左右。

## 六、下载源

国内网络建议用镜像，例如 `hf-mirror.com`。上面表里的下载链接已指向该镜像，把域名换成 `huggingface.co` 即原站。

如果模型文件在另一台机器上准备好，直接复制整个模型目录即可，不依赖任何注册表或缓存路径。
