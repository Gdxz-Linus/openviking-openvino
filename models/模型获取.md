# 模型获取

本仓库不自带模型权重。需要准备 OpenVINO IR 格式的嵌入模型，目录结构见下。

## 一、目录结构

```
<cache_dir>/harrier-ov-int8/
├── int8/
│   ├── openvino_model.xml      # 模型结构
│   ├── openvino_model.bin      # 权重
│   └── tokenizer.json          # 分词器
```

`cache_dir` 由 `ov.conf` 的 `embedding.dense.cache_dir` 指定。

## 三、转换方法

用 OpenVINO 官方工具把原始模型导出成 IR：

```bash
pip install optimum[openvino]

# 国内网络建议先设镜像
export HF_ENDPOINT=https://hf-mirror.com

optimum-cli export openvino \
  --model microsoft/harrier-oss-v1-0.6b \
  --task feature-extraction \
  --weight-format int8 \
  D:/OpenViking/models/harrier-ov-int8
```

三个参数的含义：

| 参数 | 作用 | 不写会怎样 |
| --- | --- | --- |
| `--task feature-extraction` | 指定导出为嵌入任务 | 可能按文本生成任务导出，结构不符 |
| `--weight-format int8` | 量化到 int8 | 导出 fp32，体积约为四倍 |
| 输出目录 | IR 落地位置 | — |

转换完成后把 `openvino_model.xml`、`.bin`、`tokenizer.json` 按上面的目录结构摆放。有的导出工具会把文件直接放在输出根下，需要手工移到 `int8/` 子目录，或者调整配置里的目录名来匹配。

## 四、harrier 的特殊要求

harrier 系列是解码器架构，有两处必须注意：

| 要求 | 说明 |
| --- | --- |
| 池化方式 | 必须用 last-token（`LLAMA_POOLING_TYPE_LAST = 3`），用 CLS 会让向量质量严重下降 |
| 查询前缀 | 查询侧加 `Instruct: ... Query: ` 前缀，文档侧不加，两侧向量因此不同源 |

补丁已经在模型表项里写好 `pooling_type=3` 与 `ov_query_task`，不需要手工处理。

## 五、磁盘占用

| 项目 | 体积 |
| --- | --- |
| harrier-ov-int8 模型 | 约 587 MB |
| Qwen3-Embedding-0.6B-int8-ov | 约 611 MB |
| OpenVINO 编译缓存 `ov_cache` | 约 2.1 GB，可删自动重建 |

模型体积随量化精度变化，int8 通常是 fp32 的四分之一左右。

## 六、下载源

国内网络建议用镜像，例如 `hf-mirror.com`。补丁里的 harrier 表项已经指向该镜像。

如果模型文件在另一台机器上准备好，直接复制整个模型目录即可，不依赖任何注册表或缓存路径。
